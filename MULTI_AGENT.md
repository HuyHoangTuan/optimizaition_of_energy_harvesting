# Independent SU learners

Run `python train_multi_agent.py --num-su 3 --episodes 2 --slots 20 --batch-size 8` from the project root. The equivalent module command is `python -m src.multi_agent`. Install the separate `requirements-multi-agent.txt` into your Python environment; validation used Python 3.10.20, NumPy 1.26.1 and PyTorch 2.1.0+cpu. This path uses CPU and does not import the legacy modules, create legacy logs, load historical checkpoints or open plots.

## Controlled stability study

The existing API and CLI learner/debit defaults remain unchanged. `--preset legacy-parity --debit-mode requested` explicitly selects the current legacy learner: two 128-unit layers, SGD .003, MSE, replay 100000, batch 64, gamma .99, no gradient clipping, forced random actions for 500 episodes, then the source epsilon schedule, and soft target updates with tau .001 after zero-based episodes 0,5,10,... . Explicit `--batch-size` and `--hidden` override the preset. `--double-dqn` changes only the bootstrap action-selection equation: policy argmax, target-network evaluation. The default plain DQN uses target-network max. This preset alone does not reproduce source trace generation, action shuffling, initial weights, or RNG streams.

Python callers can supply `JointEnvironment(..., trace_bank=bank, actions=exact_mapping)` or equivalent trainer keywords. Banks are validated, copied, read-only and exhausted explicitly. Requested debit subtracts `(k==0)*(1-rho)*P*Ts` next slot even after a rejected transmission; executed debit subtracts only actual transmissions. Requested mode has the separate model identifier `legacy_score_joint_actions_v1_requested_debit`. Never compare the two as though the simulator were unchanged.

`AgentConfig.legacy_parity(...)` and configurable `optimizer`, `loss`, `gradient_clip`, `exploration`, `target_schedule`, `target_tau` and `double_dqn` support controlled studies. Each independent agent retains its own network, replay, optimizer and exploration/replay RNG state. `optimize_batch` accepts an explicit batch for numerical parity tests. `end_episode` is called by the trainer; direct training loops must call it to apply episode-based target schedules. All-terminal batches use analytical target `y=reward`, while the current legacy reference raises on concatenating an empty nonterminal list.

`src.multi_agent.stability` supplies frozen evaluation, Q bounds, all-populated-state fingerprints, deterministic anchor/plain/Double-DQN selection and reward/score/execution gates. Selected-Q bounds apply only under their checked gain/noise/action assumptions and are conservative compatibility-return bounds. Frozen evaluation uses direct network inference and checks policy/target/optimizer/replay/counters/gradients/modes/private and global RNG state before/after. Fixed-peer substitutions are inference diagnostics and do not establish learning under stationary peers.

The controlled experiment used an external frozen protocol, source-matched trace bundle and recorded admission controls. Those study inputs and its original launcher are not included. Read the included [research report](RESEARCH_REPORT.md) for results and limits. Full frozen-study reproduction requires the retained external inputs; see [DRQN.md](DRQN.md) for the corrected recurrent study's input requirements.

Run a separate adapter-generated experiment with `python train_multi_agent.py --preset legacy-parity --debit-mode requested --num-su 1 --episodes 1600 --output .cache/my-fresh-run`. This command does not reproduce the exact source-parity study. Use a fresh output path. A failed parity or learning gate remains an experimental result. The results do not promote a default preset or validate physical throughput.

Each secondary transmitter has an independent feed-forward DQN Q-function, target network, configured optimizer, replay buffer, counters, initialization seed and local exploration/replay RNGs. There is no shared learned matrix. All agents select their own `(k, P, rho)` action from the same pre-step observation snapshot. A single joint environment step resolves all outcomes simultaneously. Each learner receives only its own SU reward and transition; network totals are diagnostics. This version uses feed-forward replay, not recurrent replay. Effective optimizer and all learner settings are recorded in configuration.

## Compatibility model and limits

The explicit model identifier is `legacy_score_joint_actions_v1`. Outputs are compatibility scores, not validated throughput or a rigorous upper bound. The model retains the legacy exponential-density grid called `rayleigh`, numeric dBm values inside score arithmetic, `mu = 1-rho` inside the logarithm, the primary schedule (`v=1` through the configured switch slot, then `v=0`), individual primary interference checks and harvest reward branches. This version requires exactly two PUs. Default channel-density parameter is 1 for all links; the new path does not expose the legacy heterogeneous density parameters or unused channel arrays. It does not reproduce the legacy RNG draw order or shuffled action indices.

SU i executes exactly when `k_i=0`, `mu_i*P_i*Ts <= C_i`, and `mu_i*P_i*G_sp[i,v] <= I`. Its interference is `sum(j != i, executed_j * mu_j * dBm(P_j) * G_rt[i,j])`. Harvesting and rejected transmitters produce no interference. Its executed score is `Ts*log2(1 + mu_i*dBm(P_i)*G_rt[i,i]/denominator)`, with noise plus joint interference in the denominator; when v=1, add `dBm(P_primary[i,v])*G_pr[i,v]`. Unequal rho uses a slot-average approximation; differing transmission phases are not integrated. Primary protection checks each SU independently, not aggregate SU interference. Numeric dBm arithmetic is deliberately retained and is not dimensionally valid physical power arithmetic.

Nonexecuted actions receive `-penalty`, except harvesting (`k=1`) with hypothetical transmit cost greater than available battery receives 0, matching the legacy branch. All agents harvest `rho_i*Ts*P_primary[i,v]*efficiency*G_ps[i,v] + ambient[t]`, even when transmitting or rejected. This reward shaping is unusual but explicit. Default actions use powers 1/16 through 1 watt and rho .4; `--dynamic-rho` gives rho 1/8 through 7/8. The stable unshuffled action map is saved with every run and checkpoint.

In the default executed-debit mode, only executed transmissions debit energy. Only actual transmitters interfere in both debit modes. Independent heterogeneous actions and the default debit change prevent claims of exact multi-SU baseline equivalence. Requested-debit mode supports the separately tested one-SU source-parity case. No improved performance, convergence or thesis superiority follows from smoke tests. Independent learners face a changing environment as peers learn.

## Observation and battery timing

Each agent receives only its row `[v, previous_harvest, current_pre_action_battery, G_rt[i,:], G_sp[i,:], G_pr[i,:], G_ps[i,:]]`. Receiver-row cross-link CSI is assumed available, as in the legacy state. The row contains no peer battery, selected action or reward. Current slot primary powers are used internally and are not observed. Reset returns zeros and clears time, battery, harvest, debit and record histories.

An action for slot t uses the observation returned by slot t-1. Before feasibility, compute `C(t)=clip(C(t-1)+E(t-1)-executed(t-1)*mu(t-1)*P(t-1)*Ts,0,Cmax)`. Current harvesting is credited next slot. Returned observations contain current channels, `E(t-1)` and `C(t)`; the current action debit is also applied next slot. Therefore a new action uses delayed CSI and battery information. The final action is marked terminal and subsequent steps require reset.

The regression fixture with Ts=1, Cmax=.2, mu=.6 and harvest .1 gives batteries `[0,.1,.125,.2]` for harvest, transmit P=.125, rejected transmit P=1, harvest. Execution is `[false,true,false,false]`, with only .075 debited at the following slot. It checks delayed energy and capacity clipping explicitly.

## Run artifacts

Learner defaults are two hidden layers of 64 ReLU units, Adam with learning rate .001 (PyTorch default betas/epsilon), smooth-L1/Huber Bellman loss, gamma .99, gradient norm clipping at 10, replay capacity 10000, batch size 32 in the Python API (8 in the CLI), hard target copies every 100 optimizer updates and epsilon decaying exponentially from 1 to .05 over a 500-selection scale. These are new feed-forward learner settings, not a reproduction of legacy learner hyperparameters. CLI options can change hidden width and batch size; full agent configuration is persisted.

Default runs use unique directories under ignored `.cache/multi_agent/`. `--output PATH` requires a nonexistent directory, including refusal of existing empty directories. A failed run can leave a partial directory for diagnosis; choose a fresh path to retry. Imports create no outputs. Training artifacts are written only by an explicit run.

`metadata.json` contains full environment/agent configuration, schema/model identifiers, seeds, stable action map, runtime versions, platform, start time and SHA256 hashes of implementation/entry/dependency sources. `transitions.jsonl` contains each local observation and next observation, attempted actions, local rewards, executed scores, execution masks, constraint failures, battery, harvest, deferred debit, interference, losses, terminal flags and network diagnostics. `summary.json` records per-SU reward totals, update counts and runtime. One `su_NNN.pt` file per SU contains its identity, seed, policy, target, optimizer, counters and action map.

Checkpoints support policy inspection/evaluation; they omit environment/replay/RNG state and do not provide exact training resume. Load only checkpoints you trust. Seeded repeatability is checked on this CPU runtime; cross-version or cross-platform bitwise reproducibility is not promised.

## Validation

Run `python -m unittest discover -s tests -p "test_multi_agent*.py" -v`. Tests cover the exact battery fixture, mixed actions, primary/battery rejection, receiver-row heterogeneous interference, SU permutation equivalence, local observation and reward replay, invalid-input atomicity, real isolated parameter updates, terminal-only batches, checkpoint identity, seeded repeatability, output refusal and import side effects. Short CPU CLI runs demonstrate executable optimization, not scientific performance acceptance.
